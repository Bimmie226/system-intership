# Manage projects, users, and roles 

Admin sẽ là người quản lý các project, user và role 

`Project` là những đơn vị tổ chức trong môi trường cloud mà ta có thể gán user vào. `Project` còn được gọi là `tenant`. Một `user` có thể là thành viên của 1 hoặc nhiều `project` 

`Role` xác định những hành động mà user có thể thực hiện. Ta gán `role` cho từng cặp `user-project` 

Ta có thể định nghĩa những hành động được phép đối với các role của dịch vụ OpenStack trong các tệp `/etc/PROJECT/policy.yaml`. **Ví dụ:** định nghĩa những hành động dành cho role của dịch vụ Compute trong tệp `/etc/nova/policy.yaml`

Ta có thể quản lý `project`, `user` và `role` độc lập với nhau 

Trong quá trình thiết lập môi trường cloud, đơn vị vận hành định nghĩa ít nhất 1 `project`, 1 `user` và 1 `role` 

Ta có thể thêm, cập nhật và xóa project cũng như user, gán user vào 1 hoặc nhiều project, đồng thời thay đổi hoặc loại bỏ các phép gán đó

Để kích hoạt hoặc tạm thời vô hiệu hóa 1 project hay user, hãy cập nhật project hoặc user tương ứng. Ta cũng có thể thay đổi quota ở cấp Project 

Trước khi có thể xóa một tài khoản user, ta phải loại tài khoản đó khỏi project chính (primary project) của nó.

## I. Project 

Một Project là 1 nhóm gồm từ 0 đến nhiều user 

Trong dịch vụ Compute, project sở hữu các máy ảo. Trong dịch vụ Object Storage, project sở hữu các container 

User có thể được liên kết với nhiều project. Mỗi cặp project-user có thể được gán với 1 role 

### 1.0 List Projects 

Liệt kê tất cả các project cùng ID, tên: 

```bash
openstack project list
```

```bash
(kolla-venv-2026.1) root@control-01:~/kolla-2026.1# openstack project list

| ID                               | Name    |
+----------------------------------+---------+
| 2b2204fdb3f24c5fa6b66a7575aecd8a | admin   |
| 3d9dafbd4de04dfab47a4a53b8129785 | service |
+----------------------------------+---------+
```

### 1.1 Create a Project 

Tạo 1 project có tên `new-project`: 

```bash
openstack project create --description 'my new project' new-project --domain default 
```

```bash
(kolla-venv-2026.1) root@control-01:~/kolla-2026.1# openstack project create --description 'my new project' new-project --domain default
+-------------+----------------------------------+
| Field       | Value                            |
+-------------+----------------------------------+
| description | my new project                   |
| domain_id   | default                          |
| enabled     | True                             |
| id          | 7b6b77d731b74843a4c7c5a7ecae44ee |
| is_domain   | False                            |
| name        | new-project                      |
| options     | {}                               |
| parent_id   | default                          |
| tags        | []                               |
+-------------+----------------------------------+
```

Nếu tạo project mà: 

- Không sử dụng token có phạm vi domain (domain-scoped token), tức là sử dụng token có phạm vi project (project-scoped token) hoặc phạm vi hệ thống (system-scoped token) 
- Đồng thời không chỉ định `domain` hoặc `domain_id`

Thì project sẽ tự động được tạo trong domain default 

### 1.2 Update a Project 

Chỉ định ID của project để cập nhật project đó. Ta có thể cập nhật tên, mô tả và trạng thái kích hoạt của project 

Tạm thời vô hiệu hóa 1 project: 

```bash
openstack project set PROJECT_ID --disable 
```

Để kích hoạt 1 project đang bị vô hiệu hóa: 

```bash
openstack project set PROJECT_ID --enable 
```

Để update tên project: 

```bash
openstack project set PROJECT_ID --name project-new
```

Để kiểm tra những thay đổi, hiển thị thông tin của project đã cập nhật:

```bash
openstack project show PROJECT_ID
```

```bash
(kolla-venv-2026.1) root@control-01:~/kolla-2026.1# openstack project show 7b6b77d731b74843a4c7c5a7ecae44ee
+-------------+----------------------------------+

+-------------+----------------------------------+
| description | my new project                   |
| domain_id   | default                          |
| enabled     | True                             |
| id          | 7b6b77d731b74843a4c7c5a7ecae44ee |
| is_domain   | False                            |
| name        | bim-project                      |

| parent_id   | default                          |

```

### 1.3 Delete a Project 

```bash
openstack project delete PROJECT_ID
```

### 2.1 Create a user 

Để tạo user, ta phải chỉ định tên. Ta cũng có thể tùy chọn chỉ định ID của project, mật khẩu và email. Docs chính thức khuyến nghị cung cấp ID của project và mật khẩu, vì user không thể đăng nhập vào Dashboard nếu thiếu những thông tin này

Tạo user `new-user`: 

```bash
openstack user create --project bim-project --password PASSWORD new-user
```

```bash
| options             | {}                               |

```

### 2.2 Update a user 

Ta có thể update tên, email và trạng thái kích hoạt của user 

Để có thể tạm thời vô hiệu hóa 1 tk user: 

```bash
openstack user set USER_NAME --disable 
```

Nếu vô hiệu hóa tài khoản, user sẽ không đăng nhập được vào dashboard 

Tuy nhiên, dữ liệu của tài khoản vẫn được giữ lại, vì vậy ta có thể kích hoạt lại user bất cứ lúc nào.

Để kích hoạt 1 tk user đang bị vô hiệu hóa: 

```bash
openstack user set USER_NAME --enable
```

Để thay đổi tên và mô tả của tài khoản user:

```bash
openstack user set USER_NAME --name user-new --email new-user@example.com
```

### 2.3 Delete a user 

```bash
openstack user delete USER_NAME
```

### 3.1 Create a role 

User có thể là thành viên của nhiều project. Để gán user vào nhiều project, hãy định nghĩa một role và gán role đó cho từng cặp user-project 

Tạo role `new-role`: 

```bash
openstack role create new-role
```

```bash

| Field       | Value                            |
+-------------+----------------------------------+

| name        | new-role                         |

```

### 3.2 Assign a role 

Để gán 1 user vào 1 project, ta phải gán role cho cặp user-project đó 

- Gán role cho 1 cặp user-project: 

    ```bash
    openstack role add --user USER_NAME --project PROJECT_NAME ROLE_NAME
    ```

    ```bash
    openstack role add --user user-new --project bim-project new-role 
    ```

- Kiểm tra phép gán role: 

    ```bash
    openstack role assignment list --user USER_NAME --project PROJECT_NAME --names
    ```

    ```bash
    (kolla-venv-2026.1) root@control-01:~/kolla-2026.1# openstack role assignment list --user user-new --project bim-project --names
    +----------+------------------+-------+---------------------+--------+--------+-----------+
    | Role     | User             | Group | Project             | Domain | System | Inherited |
    +----------+------------------+-------+---------------------+--------+--------+-----------+
    | new-role | user-new@Default |       | bim-project@Default |        |        | False     |
    +----------+------------------+-------+---------------------+--------+--------+-----------+
    ```

Xem thông tin chi tiết của 1 role được chỉ định:

Thu hồi 1 role khỏi cặp user-project: 

```bash
openstack role remove --user USER_NAME --project PROJECT_NAME ROLE_NAME
```

Kiểm tra việc thu hồi role: 

```bash
openstack role assignment list --user USER_NAME --project PROJECT_NAME --names
```


### 3.5 Creating implied roles 

Ta có thể xây dựng hệ thống phân cấp role bằng cách thiết lập để 1 role bao hàm các role khác 

Các role được bao hàm này được gọi là `implied roles`, còn những quan hệ tương ứng được gọi là `quy tắc suy ra role - role inference rules`

**Ví dụ:** Thiết lập role `admin` bao hàm role `member`. Nếu user được gán role nguồn (prior role) là `admin`, user cũng sẽ nhận được role `member` mà role nguồn bao hàm 

```bash
openstack implied role create admin --implied-role member
```

**NOTE:** Quan hệ bao hàm role chỉ có hiệu lực theo một chiều: từ role nguồn (prior role) đến role được suy ra (implied role). Vì vậy, việc gán role `member` cho user sẽ không cấp cho user đó role `admin`.

### 3.6 Listing implied roles 

```bash
openstack implied role list
```

```bash
(kolla-venv-2026.1) root@control-01:~/kolla-2026.1# openstack implied role list
+----------------------------------+-----------------+----------------------------------+-------------------+
| Prior Role ID                    | Prior Role Name | Implied Role ID                  | Implied Role Name |
+----------------------------------+-----------------+----------------------------------+-------------------+
| 8a84beb20ae74bb980441b13f55bb3b1 | member          | 26a6c4fa563c401f9c4221c4e6c8e9e9 | reader            |
| 5607cbdf273146d8b9d1fe8a9d224188 | admin           | 6a35932f97444e23854e9dd8e5fa4df7 | manager           |
| 6a35932f97444e23854e9dd8e5fa4df7 | manager         | 8a84beb20ae74bb980441b13f55bb3b1 | member            |
+----------------------------------+-----------------+----------------------------------+-------------------+
```

### 3.7 Deleting implied roles 

```bash
openstack implied role delete admin --implied-role member
```

**NOTE:** Thao tác xóa implied role sẽ loại bỏ quy tắc suy ra role. Thao tác này không xóa role nguồn hoặc role được suy ra. Vì vậy, nếu user được gán role nguồn, user sẽ không còn nhận được các role thông qua quy tắc suy ra vừa bị xóa.
