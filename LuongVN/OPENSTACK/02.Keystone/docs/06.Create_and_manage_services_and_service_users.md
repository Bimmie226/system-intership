# Create and manage services and service users 

## I. Service Catalog 

Các dịch vụ OpenStack có thể được tra cứu khi được đăng ký trong service catalog của Keystone 

Service catalog có thể được quản lý dưới dạng 1 tệp mẫu tĩnh (static file template) hoặc 1 bẳng cơ sở dữ liệu động 

### 1.0 File-based Service Catalog (`templated.Catalog`)

templated catalog là 1 backend hoạt động trong bộ nhớ, được khởi tạo từ tệp `template_file` chỉ đọc 

Chỉ chọn phương án này nếu ta biết rằng service catalog của mình sẽ không thay đổi nhiều theo thời gian 

**NOTE:** Việc cố gắng thay đổi service catalog khi sử dụng driver này sẽ dẫn đến lỗi `HTTP 501 Not Implemented`. Đây là hành vi được thiết kế sẵn. Nếu muốn sử dụng các lệnh thay đổi catalog, bạn phải chuyển sang driver Service Catalog dựa trên SQL.

Ví dụ cấu hình trong `keystone.conf`: 

```INI
[catalog]
driver = templated
template_file = /opt/stack/keystone/etc/default_catalog.templates
```

Giá trị của `template_file` phải là đường dẫn tuyệt đối đến tệp cấu hình service catalog.

### 1.1 SQL-based Service Catalog (`sql.Catalog`)

Đây là 1 driver động sử dụng cơ sở dữ liệu làm backend, hỗ trợ đầy đủ việc lưu trữ cấu hình bền vững 

Ví dụ cấu hình trong `keystone.conf`: 

```INI
[catalog]
driver = sql
```

**NOTE:** Không cần định nghĩa `template_file` khi sử dụng catalog dựa trên SQL.

#### 1.1.0 Create a service 

- Liệt kê các dịch vụ có sẵn: 

    ```bash
    openstack service list
    ```

    ```bash
    (kolla-venv-2026.1) root@control-01:/etc/kolla/keystone# openstack service list
    +----------------------------------+-----------+-----------+
    | ID                               | Name      | Type      |
    +----------------------------------+-----------+-----------+
    | 15f8847973cb4402848cc9cff850ec07 | glance    | image     |
    | 345c1e0e8dc34a7eae4d5c21a3381e06 | keystone  | identity  |
    | 38d25aa2a18f4cedafe9fdd51f6b6730 | placement | placement |
    | 4d007ae747bf46809a6155f74ba135f9 | nova      | compute   |
    | adf9c1e68a234d9db462f1e0f293b20b | neutron   | network   |
    +----------------------------------+-----------+-----------+
    ```

- Để tạo 1 dịch vụ: 

    ```bash
    openstack service create --name SERVICE_NAME --description SERVICE_DESCRIPTION SERVICE_TYPE
    ```

    - `service_name`: Tên duy nhất của dịch vụ mới 
    - `service_type`: Loại dịch vụ, chẳng hạn `identity`, `compute`, `network`, `image`, `object-store` hoặc một chuỗi định danh dịch vụ khác.
    - `service_description`: Mô tả dịch vụ 

    - Ví dụ: để tạo dịch vụ `swift` thuộc loại `object-store`, chạy lệnh: 

    ```bash
    openstack service create --name swift --description "object store service" object-store
    ```

- Để lấy thông tin chi tiết của 1 dịch vụ: 

    ```bash
    openstack service show SERVICE_TYPE|SERVICE_NAME|SERVICE_ID
    ```

    ```bash
    (kolla-venv-2026.1) root@control-01:/etc/kolla/keystone# openstack service show image
    +-------------+----------------------------------+
    | Field       | Value                            |
    +-------------+----------------------------------+
    | id          | 15f8847973cb4402848cc9cff850ec07 |
    | name        | glance                           |
    | type        | image                            |
    | enabled     | True                             |
    | description | Openstack Image                  |
    +-------------+----------------------------------+
    ```

#### 1.1.1 Create an endpoint 

- Sau khi tạo dịch vụ, đăng ký 1 endpoint cho dịch vụ đó: 

    ```bash
    openstack endpoint create nova public http://example.com/compute/v2.1
    ```

#### 1.1.2 Delete a service 

```bash
openstack service delete SERVICE_TYPE|SERVICE_NAME|SERVICE_ID
```

## II. Service users 

Mỗi dịch vụ như Nova, Neutron, Glance… cần một tài khoản riêng trong Keystone để phần mềm đó xác thực và thực hiện những lời gọi API cần quyền.

Service user là tài khoản dành cho phần mềm sử dụng. Về bản chất, nó vẫn là một user trong Keystone, có tên, thông tin xác thực và được gán role.

**Ví dụ:** Tạo service user cho các dịch vụ Compute, Block Storage và Networking 

Để cấu hình các dịch vụ OpenStack sử dụng service user: 

- Tạo 1 project dùng chung cho tất cả dịch vụ 
- Tạo user cho từng dịch vụ 
- Gán role `admin` cho từng cặp service user-project 

Role này cho phép các service user xác minh token, đồng thời thực hiện xác thực (authentication) và phân quyền (authorization) đối với các yêu cầu khác của người dùng.

### 2.0 Create service users 

- Tạo project dành cho các service users: Thông thường các project này thường được đặt tên là `service`

    ```bash
    openstack project create service --domain default
    ```

- Tạo service user cho những dịch vụ được sử dụng trong hệ thống triển khai.

    ```bash
    openstack user create nova --password Sekr3tPass
    ```

- Gán role `admin` cho cặp user-project 

    ```bash
    openstack role add --project service --user nova admin
    ```

### 2.1 Configuring service tokens 

Nhiều thao tác trong OpenStack yêu cầu nhiều dịch vụ giao tiếp với nhau thay mặt người dùng

**Ví dụ:** Dịch vụ image lưu trữ image của người dùng trong dịch vụ Object Storage. Nếu image có kích thước rất lớn, thao tác có thể thất bại do token của người dùng hết hạn trong quá trình upload 

Trong tình huống trên, dịch vụ image sẽ đính kèm cả token của người dùng lẫn token của chính dịch vụ đó được gọi là `service token`: 

```bash
+----------------+
|      User      |
+-------+--------+
        | Access Image Data Request
        | X-AUTH-TOKEN: <end user token>
        |
+-------v---------+
|     Glance      |
+-------+---------+
        | Access Image Data Request
        | X-AUTH-TOKEN: <original end user token>
        | X-SERVICE-TOKEN: <glance service user token>
        |
+-------v---------+
|      Swift      |
+-----------------+
```

Khi một dịch vụ nhận lời gọi từ dịch vụ khác, dịch vụ nhận sẽ kiểm tra rằng token có các role phù hợp dành cho một service user.

Việc này được cấu hình trong phần [keystone_authtoken] của tệp cấu hình riêng của từng dịch vụ.

Nếu service token hợp lệ, thao tác sẽ được cho phép ngay cả khi token của người dùng đã hết hạn.

Tùy chọn service_token_roles xác định danh sách các role mà service token phải có để được xem là một service token hợp lệ.

Trong các bước trước, ta đã gán role `admin` cho các service user. Vì vậy, hãy đặt tùy chọn này thành `admin`, đồng thời đặt `service_token_roles_required` thành `true`:

```INI
[keystone_authtoken]
service_token_roles = admin
service_token_roles_required = true
```
