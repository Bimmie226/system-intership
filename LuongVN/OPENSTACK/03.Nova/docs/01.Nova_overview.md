# Nova Overview

## I. Nova là gì?

**Nova** là dịch vụ Compute của OpenStack, cung cấp API để tạo và quản lý các instance. Trong tài liệu này, instance được hiểu là một máy ảo (VM).

Nova điều phối việc cấp phát tài nguyên trên các compute host. Với triển khai KVM thường gặp, `nova-compute` sử dụng driver libvirt để quản lý máy ảo chạy bằng QEMU/KVM. Nova cũng có thể phối hợp với Ironic để cung cấp máy chủ bare metal.

Người dùng thao tác qua Horizon, OpenStackClient hoặc REST API. Các dịch vụ Nova xử lý yêu cầu ở phía sau. Xem [giới thiệu Nova](https://docs.openstack.org/nova/latest/).

## II. Chức năng chính

| Chức năng | Ý nghĩa |
|---|---|
| Tạo instance | Tiếp nhận yêu cầu, chọn compute host và điều phối khởi tạo VM |
| Quản lý vòng đời | Start, stop, reboot, rebuild và xóa instance |
| Resize | Thay đổi flavor; có bước xác nhận hoặc quay lại cấu hình cũ |
| Migration | Di chuyển VM giữa các compute host khi đáp ứng điều kiện của từng loại migration |
| Rescue | Khởi động môi trường cứu hộ để sửa hệ điều hành của VM |
| Evacuate | Dựng lại instance trên host khác khi compute nguồn gặp sự cố |
| Console | Cung cấp khả năng truy cập console thông qua cơ chế đã cấu hình |

Khả năng thực hiện từng thao tác phụ thuộc compute driver, storage và cấu hình triển khai. Có thể tra cứu thêm trong [tài liệu người dùng Nova](https://docs.openstack.org/nova/latest/user/index.html).

## III. Các khái niệm cơ bản

| Khái niệm | Giải thích |
|---|---|
| Instance / Server | Máy ảo được quản lý qua Compute API; có UUID riêng |
| Compute host | Máy chủ chạy dịch vụ `nova-compute` và cung cấp tài nguyên cho instance |
| Hypervisor | Công nghệ thực thi máy ảo, ví dụ KVM kết hợp QEMU |
| Image | Mẫu hệ điều hành dùng để khởi tạo đĩa của VM |
| Flavor | Cấu hình tài nguyên của VM: vCPU, RAM, root disk và các thuộc tính bổ sung |
| Key pair | Khóa công khai được cung cấp cho instance để hỗ trợ đăng nhập SSH |
| Project | Phạm vi sở hữu và sử dụng tài nguyên của người dùng |
| Quota | Giới hạn tài nguyên một project được phép sử dụng |

Ví dụ, flavor có `2 vCPU`, `2048 MB RAM`, `20 GB disk` mô tả cấu hình VM. Nếu VM boot từ Cinder volume, kích thước root disk được xác định bởi volume; trường root disk của flavor không mở rộng volume đó. Xem [Flavors](https://docs.openstack.org/nova/latest/user/flavors.html).

## IV. Nova phối hợp với các dịch vụ khác

| Dịch vụ | Vai trò trong yêu cầu tạo VM |
|---|---|
| Keystone | Xác thực danh tính và cung cấp service catalog; Nova kiểm tra quyền theo policy |
| Glance | Cung cấp image hệ điều hành |
| Neutron | Cung cấp kết nối mạng, port, IP và security group |
| Placement | Theo dõi tài nguyên và hỗ trợ tìm nơi đáp ứng yêu cầu |
| Cinder | Cung cấp block volume để boot hoặc gắn thêm vào VM |
| Horizon | Giao diện web để người dùng gửi yêu cầu tới các API |

Ví dụ: khi tạo một VM Ubuntu, Nova phối hợp với Glance để lấy image, Neutron để chuẩn bị mạng và Placement để cấp phát tài nguyên. Nếu boot từ volume, quá trình còn có Cinder tham gia. Xem [các dịch vụ Nova sử dụng](https://docs.openstack.org/nova/latest/#what-is-nova).

## V. Đĩa do Nova quản lý và Cinder volume

| Tiêu chí | Đĩa do Nova quản lý | Cinder volume |
|---|---|---|
| Ví dụ | Root disk khi boot từ image, đĩa ephemeral bổ sung | Root volume khi boot từ volume, data volume |
| Backend | Có thể là local disk hoặc backend dùng chung như Ceph | Backend do Cinder quản lý |
| Vòng đời | Gắn với vòng đời instance | Là tài nguyên riêng; hành vi khi xóa VM phụ thuộc `delete_on_termination` |

Đĩa ephemeral vẫn tồn tại qua lần reboot thông thường, nhưng bị xóa khi instance bị xóa. Với volume, cần kiểm tra cấu hình xóa kèm instance trước khi coi dữ liệu là được giữ lại. Xem [Block storage trong Nova](https://docs.openstack.org/nova/latest/admin/architecture.html#block-storage).

VM boot từ volume có thể hiển thị `N/A (booted from volume)` ở cột Image. Có thể truy ngược image nguồn qua `volume_image_metadata` của volume. Xem [Launch an instance from a volume](https://docs.openstack.org/nova/latest/user/launch-instance-from-volume.html).

## VI. Trạng thái của instance

| Trạng thái hiển thị | Ý nghĩa cơ bản |
|---|---|
| `BUILD` | Đang được khởi tạo |
| `ACTIVE` | Nova ghi nhận instance đang hoạt động |
| `SHUTOFF` | Đã tắt |
| `PAUSED` / `SUSPENDED` | Đang ở chế độ pause / suspend |
| `VERIFY_RESIZE` | Chờ xác nhận hoặc revert sau resize / cold migration |
| `RESCUE` | Đang ở chế độ cứu hộ |
| `ERROR` | Nova ghi nhận lỗi cần điều tra |

Các trường cần phân biệt khi đọc `server show`:

- `status`: trạng thái hiển thị qua API.
- `OS-EXT-STS:vm_state`: trạng thái nội bộ của instance.
- `OS-EXT-STS:task_state`: tác vụ đang xử lý; `None` nghĩa là không ghi nhận tác vụ hiện hành.

`ACTIVE` chưa đảm bảo ứng dụng bên trong VM đã sẵn sàng. `task_state = None` cũng chưa đủ để kết luận VM hoặc dữ liệu không có vấn đề. Xem [VM states and transitions](https://docs.openstack.org/nova/latest/reference/vm-states.html).

## VII. Các lệnh quan sát ban đầu

Các lệnh dưới đây chạy trong terminal Linux có OpenStackClient và credentials phù hợp. Một số thông tin hạ tầng yêu cầu quyền quản trị.

```bash
# Với lab Kolla-Ansible
source /etc/kolla/admin-openrc.sh

# Tài nguyên để tạo VM
openstack image list
openstack flavor list
openstack network list

# Instance hiện có
openstack server list
openstack server show <VM_NAME_OR_UUID>

# Compute service và hypervisor
openstack compute service list --service nova-compute
openstack hypervisor list
```

Thay các giá trị trong `<...>` bằng tên hoặc UUID thực tế. Tiếp tục với [Nova Architecture](02.Nova_architecture.md) để hiểu cách các thành phần xử lý yêu cầu, rồi đọc [Nova File log](03.Nova_file_log.md) để theo dõi quá trình đó khi vận hành.
