# Time Series Database Deep Dive

## I. Khó khăn của các cơ sở dữ liệu thông thường khi lưu trữ time series là gì ? 

Hãy tưởng tượng ta đang thiết kế một hệ thống giám sát cho một nhà cung cấp dịch vụ cloud với tài nguyên như sau: 
- 100.000 server 
- Mỗi server gửi 5 metrics sau mỗi 10 giây 
- Các metric bao gồm: 
  - CPU usage 
  - Memory
  - Disk I/O
  - Network traffic 

Điều này tương đương với khoảng 50.000 metric mỗi giây hay 4,3 tỷ data point mỗi ngày. 

Ngoài ra, người dùng còn muốn truy vấn dữ liệu này để: 
- Xem dashboard
- Thiết lập cảnh báo (alert) 
- ...

Ta sẽ thử lưu dữ liệu bằng 1 hệ quản trị cơ sở dữ liệu thông thường. Giả sử ta sẽ tạo một bảng như sau: 

```sql 
CREATE TABLE metrics {
  timestamp TIMESTAMP, 
  host VARCHAR(255), 
  metric_name VARCHAR(255), 
  value DOUBLE PRECISION
};
```

Với 4,3 tỷ row mỗi ngày, chúng ta sẽ phải xử lý khoảng 30 tỷ row mỗi tuần. Ngay cả khi sử dụng index, những truy vấn như: `Hiển thị mức sử dụng CPU trung bình của host-42 trong một giờ vừa qua` cũng sẽ trở nên cực kỳ chậm. 

Đồng thời hệ thống cần xử lý thông lượng ghi tối thiểu: 50.000 writes/second và con số này còn có thể tăng cao hơn rất nhiều trong những thời điểm có lưu lượng đột biến. Khối lượng ghi như vậy có thể khiến một Postgres/MariaDB instance đơn lẻ bị quá tải 

Cách lưu trữ trên cũng sẽ thiếu hiệu quả, mỗi row đều phải lưu lại đầy đủ: `host`, `metric_name`. Các giá trị như `host-42`, `cpu-usage` sẽ bị lặp lại trong hàng triệu hoặc hàng tỷ row. Điều này khiến kích thước lưu trữ có thể tăng lên khoảng: 50 - 100 byte cho mỗi data point trong khi thông tin thực sự quan trọng của mỗi data point chỉ gồm: `timestamp + value` = 8 byte + 8byte = 16 byte -> Một lượng lớn dung lượng lưu trữ vì vậy bị tiêu tốn cho những dữ liệu metadata bị lặp lại.

Ta có thể làm tốt hơn rất nhiều với các **Time-Series Database** như: InfluxDB, TimescaleDB, Prometheus được xây dựng đặc biệt để xử lý loại workload này. 

## II. Time-Series Storage Engine 

### 2.0 Mô hình dữ liệu 

Các cơ sở dữ liệu chuỗi thời gian thường tổ chức dữ liệu thành: 

- `Metrics` - giống như các bảng (Ví dụ: `cpu_usage`, `memory`, ...)
- `Tags` - metadata được đánh index để lọc (Ví dụ: `host="server-1"`, `region="us-west"`, ...)
- `Fields` - Các giá trị thực tế được đo (Ví dụ: `value=45,2`)
- `Timestamp` - Thời điểm phép đo được thực hiện 

Một data point có thể trông như thế này: 

```bash
cpu_usage,host=server-1,region=us-west value=45.2 1699999200000000000
└─────────────────────────────────────┘ └────────┘ └─────────────────┘
        metric + tags               field          timestamp
```

### 2.1 Storage Engine 

Một time-series storage engine điển hình kết hợp các pattern sau: 

- `Write Ahead Log (WAL)`: Dữ liệu trước tiên được ghi vào WAL để đảm bảo tính bền vững. Nếu database bị crash, nó có thể khôi phục dữ liệu chưa được commit từ WAL 
- `In-Memory Buffer`: Dữ liệu cũng được ghi vào 1 buffer trong bộ nhớ
- `Flush to Disk`: Khi buffer đạt đến một ngưỡng nhất định, nó được flush xuống disk dưới dạng một file immutable với timestamps và values đã được nén


### 2.2 Thực thi truy vấn 

Khi ta truy vấn một cơ sở dữ liệu chuỗi thời gian: 

```sql 
SELECT mean(value) FROM cpu_usage 
WHERE host = 'server-1'
  AND time > now() - 1h
GROUP BY time(5m)
```

Query engine: 

1. Xác định các partition liên quan dựa trên bộ lọc thời gian. Chỉ những partition giao với khoảng thời gian của query mới được xem xét 

2. Xác định các series bằng cách tra cứu bộ lọc tag (`host='server-1'`) trong tag index nằm trong bộ nhớ.

3. Đọc từ buffer và các file trên disk. Buffer chứa dữ liệu mới nhất; các file trên disk chứa dữ liệu cũ hơn. Các kết quả được merge lại.

### 2.3 Ví dụ thực tế: Multi-Tag Query 

Ta sẽ theo dõi một ví dụ hoàn chỉnh để xem dữ liệu di chuyển từ lúc ingestion cho đến khi tạo ra kết quả query như thế nào 

#### Bước 1: Data Ingestion

Ví dụ ta có hệ thống monitoring ghi các data point sau trong khoảng vài giây: 

```bash
cpu_usage,host=server-1,region=us-west,env=prod value=45.2 1700000000000000000
cpu_usage,host=server-1,region=us-west,env=prod value=47.1 1700000010000000000
cpu_usage,host=server-2,region=us-west,env=prod value=62.3 1700000000000000000
cpu_usage,host=server-2,region=us-west,env=prod value=61.8 1700000010000000000
cpu_usage,host=server-3,region=us-east,env=prod value=38.9 1700000000000000000
cpu_usage,host=server-3,region=us-east,env=prod value=39.2 1700000010000000000
cpu_usage,host=server-4,region=us-east,env=staging value=71.0 1700000000000000000
cpu_usage,host=server-4,region=us-east,env=staging value=73.5 1700000010000000000
```

#### Bước 2: Cách dữ liệu được tổ chức 

Mỗi tổ hợp duy nhất của `metrics + tags` tạo ra 1 `series`. Dữ liệu của ta có 4 series: 

```bash
Series 1: cpu_usage,host=server-1,region=us-west,env=prod
Series 2: cpu_usage,host=server-2,region=us-west,env=prod
Series 3: cpu_usage,host=server-3,region=us-east,env=prod
Series 4: cpu_usage,host=server-4,region=us-east,env=staging
```

Dữ liệu được lưu ở disk như sau: 

```bash
┌─────────────────────────────────────────────────────────────────────────┐
│ Data File (partition for Nov 15, 2023)                                  │
├─────────────────────────────────────────────────────────────────────────┤
│ Block 0: Series 1 (server-1, us-west, prod)                             │
│                                                                         │
│   Raw timestamps:    [1700000000000000000, 1700000010000000000] (16 bytes)
│   Stored as:         base=1700000000, delta=10, Δ-of-Δ=[0]       (3 bytes)
│                                                                         │
│   Raw values:        [45.2, 47.1]                                (16 bytes)
│   Stored as:         [45.2, XOR-diff]                           (10 bytes)
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│ Block 1: Series 2 (server-2, us-west, prod)                             │
│   Raw:    ts=[1700000000, 1700000010], vals=[62.3, 61.8]        (32 bytes)
│   Stored: ts=base+Δ+[0], vals=[62.3, XOR-diff]                  (13 bytes)
├─────────────────────────────────────────────────────────────────────────┤
│ Block 2: Series 3 (server-3, us-east, prod)                             │
│   Raw:    ts=[1700000000, 1700000010], vals=[38.9, 39.2]        (32 bytes)
│   Stored: ts=base+Δ+[0], vals=[38.9, XOR-diff]                  (13 bytes)
├─────────────────────────────────────────────────────────────────────────┤
│ Block 3: Series 4 (server-4, us-east, staging)                          │
│   Raw:    ts=[1700000000, 1700000010], vals=[71.0, 73.5]        (32 bytes)
│   Stored: ts=base+Δ+[0], vals=[71.0, XOR-diff]                  (13 bytes)
├─────────────────────────────────────────────────────────────────────────┤
│ INDEX                                                                   │
│   "cpu_usage,host=server-1,region=us-west,env=prod"  → Block 0          │
│   "cpu_usage,host=server-2,region=us-west,env=prod"  → Block 1          │
│   "cpu_usage,host=server-3,region=us-east,env=prod"  → Block 2          │
│   "cpu_usage,host=server-4,region=us-east,env=staging" → Block 3        │
└─────────────────────────────────────────────────────────────────────────┘
```

Database cũng duy trì một tag index trong bộ nhớ, ánh xạ các giá trị tag tới các series.

```bash
Tag Index (in memory):
┌─────────────────────────────────────────────────────────────────────────┐
│ region=us-west  → [Series 1, Series 2]                                  │
│ region=us-east  → [Series 3, Series 4]                                  │
│ env=prod        → [Series 1, Series 2, Series 3]                        │
│ env=staging     → [Series 4]                                            │
│ host=server-1   → [Series 1]                                            │
│ host=server-2   → [Series 2]                                            │
│ host=server-3   → [Series 3]                                            │
│ host=server-4   → [Series 4]                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

#### Bước 3: Thực thi 1 Multi-Tag Query 

Bây giờ query: `Mức sử dụng CPU trung bình của các production server trong us-west là bao nhiêu ?`

```sql 
SELECT mean(value) FROM cpu_usage 
WHERE region = 'us-west' AND env = 'prod' AND time >= 1700000000000000000 AND time <= 1700000010000000000
```

Đây là cách database xử lý query này: 

```bash
query: region='us-west' AND env='prod'

Bước 1: Tra cứu tag index 

        region = us-west -> [Series 1, Series 2]
        env=prod         -> [Series 1, Series 2, Series 3]

Bước 2: Lấy giao của các tập hợp 

        [Series 1, Series 2] ∩ [Series 1, Series 2, Series 3] = [Series 1, Series 2]

Bước 3: Tra cứu vị trí block trong file index 

        Series 1 -> Block 0

        Series 2 -> Block 1

Bước 4: Chỉ đọc block 0 và 1 từ disk (bỏ qua block 2, 3!)

        Block 0: timestamps [1700000000, 1700000010], values [45.2, 47.1] 
        
        Block 1: timestamps [1700000000, 1700000010], values [62.3, 61.8]

Bước 5: Áp dụng bộ lọc thời gian (trong trường hợp này tất cả các point đều khớp)

Bước 6: Tính aggregation 

        mean([45.2, 47.1, 62.3, 61.8]) = 54.1
```
