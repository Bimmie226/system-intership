# Tìm Hiểu Telegraf & Telegraf Prometheus Exporter

## I. Tổng quan

### 1.0 Telegraf là gì?

**Telegraf** là một agent mã nguồn mở được phát triển bởi InfluxData, dùng để **thu thập, xử lý, tổng hợp và gửi metrics/events** từ nhiều nguồn khác nhau tới các hệ thống lưu trữ hoặc giám sát.

Telegraf được viết bằng **Go** và hoạt động theo kiến trúc **plugin-based**.

Có thể hiểu đơn giản:

> **Telegraf là một agent trung gian đứng giữa nguồn sinh metrics và hệ thống monitoring/storage.**

Ví dụ:

```text
Linux Server
    │
    │ CPU / RAM / Disk / Network
    ▼
 Telegraf
    │
    ├──► Prometheus
    ├──► InfluxDB
    ├──► Kafka
    ├──► OpenTelemetry
    └──► Các hệ thống khác
```

Khác với một exporter chỉ phục vụ một mục đích cụ thể, Telegraf có thể thu thập dữ liệu từ rất nhiều loại hệ thống thông qua các plugin.

---

### 1.1 Telegraf Exporter là gì?

Thực tế, **Telegraf Exporter** không phải là một sản phẩm riêng biệt.

Telegraf có thể hoạt động giống một **Prometheus Exporter** khi sử dụng:

```toml
[[outputs.prometheus_client]]
```

Plugin này mở một HTTP endpoint, mặc định có thể cấu hình như:

```text
http://SERVER_IP:9273/metrics
```

Prometheus sau đó scrape endpoint này tương tự như cách scrape:

```text
Node Exporter
Blackbox Exporter
MySQL Exporter
Redis Exporter
```

Mô hình:

```text
                     SERVER
              ┌─────────────────┐
              │                 │
CPU ─────────►│                 │
Memory ──────►│    Telegraf     │
Disk ────────►│                 │
Network ─────►│                 │
Docker ──────►│                 │
SNMP ────────►│                 │
              └────────┬────────┘
                       │
                       │ :9273/metrics
                       ▼
                  Prometheus
                       │
                       ▼
                    Grafana
```

Trong mô hình này:

```text
Telegraf = Collector + Processor + Prometheus Exporter
```

---

## II. Tại sao cần Telegraf?

Trong một hệ thống monitoring thông thường, chúng ta có thể phải triển khai nhiều exporter:

```text
Server
 ├── Node Exporter
 ├── MySQL Exporter
 ├── Redis Exporter
 ├── SNMP Exporter
 └── Custom Exporter
```

Điều này hoàn toàn hợp lý và Prometheus exporter vẫn là cách triển khai rất phổ biến.

Tuy nhiên, trong những môi trường có nhiều loại nguồn dữ liệu khác nhau, Telegraf cho phép xây dựng một pipeline thống nhất:

```text
                    Telegraf
                       │
       ┌───────────────┼───────────────┐
       │               │               │
      CPU            MySQL           SNMP
       │               │               │
       └───────────────┼───────────────┘
                       │
                   Processing
                       │
                       ▼
                  /metrics:9273
                       │
                       ▼
                   Prometheus
```

Điểm mạnh lớn của Telegraf vì vậy không đơn thuần nằm ở việc **export metrics**, mà nằm ở khả năng:

**Collect → Process → Aggregate → Output**

---

## III. Kiến trúc của Telegraf

Telegraf sử dụng kiến trúc plugin.

Bốn thành phần quan trọng nhất là:

```text
Input Plugins
      │
      ▼
Processor Plugins
      │
      ▼
Aggregator Plugins
      │
      ▼
Output Plugins
```

Có thể hình dung toàn bộ pipeline:

```text
┌───────────────────────────────────────────────────────────────┐
│                         TELEGRAF                              │
│                                                               │
│  INPUT             PROCESSOR          AGGREGATOR              │
│                                                               │
│  CPU ───────┐                                                 │
│  Memory ────┤       Rename           Mean                     │
│  Disk ──────┤─────► Convert ──────►  Min  ────────┐           │
│  Docker ────┤       Filter           Max          │           │
│  MySQL ─────┤       Add tags         Quantile     │           │
│  SNMP ──────┘                                     │           │
│                                                   ▼           │
│                                                OUTPUT         │
│                                                   │           │
│                            ┌──────────────────────┼────────┐  │
│                            ▼                      ▼        ▼  │
│                       Prometheus              InfluxDB  Kafka │
└───────────────────────────────────────────────────────────────┘
```

### 3.0 Input Plugin

#### 3.0.0 Input Plugin là gì?

Input Plugin chịu trách nhiệm:

> **Thu thập dữ liệu từ nguồn bên ngoài và đưa dữ liệu vào Telegraf.**

Nguồn dữ liệu có thể là:

- Operating System
- Application
- Database
- Container
- Network Device
- Message Queue
- Cloud Service
- API
- IoT Device

Ví dụ:

```text
Linux CPU
   │
   ▼
inputs.cpu
   │
   ▼
Telegraf
```

---

#### 3.0.1 Một số Input Plugin phổ biến

##### CPU

```toml
[[inputs.cpu]]
  percpu = true
  totalcpu = true
```

Thu thập thông tin CPU.

---

##### Memory

```toml
[[inputs.mem]]
```

Thu thập thông tin RAM.

---

##### Disk

```toml
[[inputs.disk]]
```

Thu thập:

```text
disk usage
free space
used space
inode
...
```

---

##### Disk I/O

```toml
[[inputs.diskio]]
```

Thu thập I/O của disk:

```text
read
write
IOPS
latency-related counters
...
```

---

##### Network

```toml
[[inputs.net]]
```

Thu thập:

```text
bytes received
bytes sent
packets
errors
drops
...
```

---

##### Docker

```toml
[[inputs.docker]]
```

Cho phép thu thập metrics từ Docker.

---

##### MySQL

```toml
[[inputs.mysql]]
```

Thu thập metrics từ MySQL/MariaDB.

---

##### SNMP

```toml
[[inputs.snmp]]
```

Đây là một plugin rất hữu ích khi monitoring:

```text
Router
Switch
Firewall
UPS
Storage
Network appliance
```

---

### 3.1 Processor Plugin

Processor Plugin được sử dụng để **biến đổi metrics trước khi gửi đi**.

Ví dụ:

```text
Input
  │
  ▼
CPU metric
  │
  ▼
Processor
  │
  ├── rename
  ├── convert
  ├── filter
  └── add tag
  │
  ▼
Output
```

Ví dụ chúng ta thu được:

```text
cpu_usage
```

Processor có thể biến đổi thành:

```text
server_cpu_usage
```

Hoặc thêm metadata:

```text
server_cpu_usage{
    environment="production",
    datacenter="hanoi"
}
```

Processor đặc biệt hữu ích khi doanh nghiệp muốn **chuẩn hóa metrics và labels/tags** trước khi dữ liệu đi vào monitoring backend.

---

### 3.2 Aggregator Plugin

Aggregator được sử dụng để **tổng hợp nhiều metric trong một khoảng thời gian**.

Ví dụ CPU được thu thập:

```text
10s → 30%
20s → 40%
30s → 50%
40s → 60%
```

Aggregator có thể tạo:

```text
AVG CPU = 45%
MAX CPU = 60%
MIN CPU = 30%
```

Pipeline:

```text
Raw Metrics
    │
    ▼
Aggregator
    │
    ├── mean
    ├── min
    ├── max
    ├── quantile
    └── standard deviation
    │
    ▼
Aggregated Metrics
```

Aggregator thường hoạt động theo một **time window (`period`)**.

Ví dụ:

```text
period = 1m
```

có nghĩa là aggregate dựa trên metrics trong cửa sổ khoảng một phút.

---

### 3.3 Output Plugin

Output Plugin xác định:

> **Telegraf sẽ gửi dữ liệu đi đâu.**

Ví dụ:

```text
                Telegraf
                    │
       ┌────────────┼────────────┐
       │            │            │
       ▼            ▼            ▼
    InfluxDB      Kafka      Prometheus
```

Telegraf hỗ trợ nhiều loại output khác nhau.

Ví dụ:

```toml
[[outputs.influxdb_v2]]
```

hoặc:

```toml
[[outputs.prometheus_client]]
```
