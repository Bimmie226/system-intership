# Tìm hiểu về GitOps 

## I. GitOps là gì ? 

### 1.0 Định nghĩa 
GitOps là một phương pháp quản lý cơ sở hạ tầng và ứng dụng bằng cách sử dụng Git làm nguồn chân lý duy nhất (single source of truth). Mọi thay đổi về cấu hình, code, và cơ sở hạ tầng đều được quản lý thông qua các repository Git. 

### 1.1 Tại sao GitOps quan trọng ? 
- `Tính minh bạch`: Mọi thay đổi được theo dõi và quản lý thông qua Git 
- `Tự động hóa`: Tự động hóa việc triển khai và đồng bộ hóa cơ sở hạ tầng với trạng thái mong muốn 
- `Kiểm soát phiên bản`: Quản lý và theo dõi mọi thay đổi thông qua hệ thống quản lý phiên bản 

## II. Cách GitOps hoạt động 

GitOps vận hành dựa trên sự kết hợp của 3 thành phần chính: Git repository, GitOps agent (operator) và hệ thống đích (thường là K8s cluster) 

### 2.0 Khai báo trạng thái mong muốn trong Git 
Trước tiên, đội ngũ phát triển hoặc vận hành sẽ khai báo trạng thái mong muốn của hệ thống trong Git repository. Các cấu hình này có thể bao gồm Kubernetes manifest, Helm chart, Terraform file

Mọi thay đổi đều được thực hiện thông qua commit hoặc pull request, giúp quá trình cập nhật có thể được kiểm tra, phê duyệt và truy vết rõ ràng.

### 2.1 Git là nguồn cấu hình trung tâm 

Git đóng vai trò là nơi lưu trữ trạng thái mong muốn của hệ thống. Đây là nơi developer và đội ngũ vận hành tương tác để thay đổi cấu hình, thay vì chỉnh sửa trực tiếp trên cluster. Lịch sử commit trong Git giúp ghi lại đầy đủ các thay đổi, hỗ trợ kiểm tra, audit log và rollback khi cần

### 2.2 Cơ chế triển khai: Push-based và Pull-based 

- `Push-based`: Pipeline CI/CD bên ngoài (Jenkins, Gitlab CI) phát hiện thay đổi trong Git và push cấu hình mới vào cluster. Mô hình này đơn giản nhưng yêu cầu pipeline có quyền vào trong cluster
- `Pull-based`: Agent bên trong cluster liên tục pull Git repo để phát hiện thay đổi, sau đó tự đồng bộ. Mô hình này được đánh giá là phù hợp hơn với GitOps 

### 2.3 Đối chiếu liên tục 

Agent không chỉ áp dụng thay đổi một lần rồi dừng, nó liên tục so sánh trạng thái thực tế (actual state) với trạng thái mong muốn (desired state) trong Git. Nếu phát hiện "configuration drift" (ví dụ ai đó chỉnh sửa cluster thủ công), agent sẽ tự động khôi phục về trạng thái khai báo trong Git.

### 2.4 Sự kết hợp với Immutable Infrastructure 

GitOps hoạt động hiệu quả nhất khi đi kèm với Immutable Infrastructure - mô hình hạ tầng bất biến, trong đó các thành phần (server, container, VM) không bao giờ được sửa đổi sau khi triển khai. Thay vào đó, mọi cập nhật đều được thực hiện bằng cách tạo phiên bản mới và thay thế hoàn toàn phiên bản cũ.

## III. Lợi ích của GitOps 

**Tự động hóa triển khai và rollback:** 

GitOps giúp tự động hóa toàn bộ quá trình triển khai. Developer chỉ cần push code hoặc merge pull request, hệ thống sẽ tự đồng bộ thay đổi lên cluster. Khi có lỗi, rollback cũng rất đơn giản, chỉ cần git revert là hệ thống tự quay về trạng thái ổn định trước đó.

**Tăng độ ổn định và khả năng self-healing:** 

Git luôn được xem là `Single source of Truth`, vì vậy nếu có ai chỉnh sửa trực tiếp trên production, hệ thống sẽ tự phát hiện và đưa cluster quay về đúng trạng thái đã khai báo trong Git 

**Bảo mật và dễ kiểm soát:** 

Mọi thay đổi đều phải đi qua pull request và review nên hạn chế được thao tác thủ công nguy hiểm trên production. Đồng thời Git log lưu lại đầy đủ ai thay đổi gì, vào thời điểm nào và vì lý do gì, giúp việc audit và truy vết trở nên dễ dàng hơn.
